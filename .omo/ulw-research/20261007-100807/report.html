ULW-Research report

zix x machine0 x Railway: lightweight agent images with any-package acquisition

Integrating the zix CLI into machine0, building a Railway template lighter than the DeepSeek-Harness-on-NixOS reference, and moving omo-native to the stable 5.1.22 channel.

2026-10-07 - session 20261007-100807 - every number below is tagged MEASURED, ASSUMED or DERIVED and cited to a source or a run transcript.

Executive summary

Three deliverables shipped and were proven by execution [S5][S15]. First, the zix CLI grew its runtime half: zix get NAME[@VERSION] installs any nixpkgs version that ever shipped into the calling user's profile, in seconds, without evaluating nixpkgs, and without needing a repository on disk. It is integrated into the machine0 project both as the in-image CLI agents use (zix get) and as repo tooling (nix run .#zix -- pkg add against modules/packages.nix).

Second, railway-nix-agent is a locally validated Railway image: an alpine base with nix, the agent on loopback behind Caddy basic auth, an open /healthz that proxies to the agent, and the same zix runtime acquisition inside the container. Measured: MEASURED a 2016 version installs in 1-2 s and a latest package in 5 s inside a fresh container whose peak memory across boot plus three installs measured 303 MiB in the final run (398 MiB on a re-run; cgroup v2 counts page cache) - the fast path is what removes the 1 GB floor the reference template has to declare, while a 512 MB plan remains a bench-level observation rather than a promise. The image compresses to 394 MiB against the reference's 588.7 MB, on a 44.2 MiB base against its 154 MB one [S2][S14][S15].

Third, omo-native packaging moved from omo-ai@beta 5.0.0-0.beta.82 to the stable omo-ai@5.1.22 (npm latest; the beta tag is parked at 5.1.0), verified by build and by an independent re-derivation of the lockfile hash: the built binary reports omo 5.1.22 (engine: senpi 2026.10.10-5).

Key findings

1. The acquisition mechanism and its honest limits

nixpkgs-multiverse maps every nixpkgs version Hydra ever built to the store path its build produced. The fast path fetches that path from cache.nixos.org with zero nixpkgs evaluation: three flake files are evaluated and about 25 MB of JSON is parsed instead [S1], which a counter-measurement reduced from the review's imprecise "skips evaluation entirely" wording (233 evaluated files on the eval road versus 6-7 on the fast road) [S5][S15]. Limits are real and documented in the tool: attrs the index never matched and versions newer than the index pin fall back to the evaluating road, and pre-2016 builds can substitute yet crash on modern locale data [S1][S15].

2. machine0 integration

The image ships the vendored zix CLI, a read-only runtime manifest at /etc/zix/zix.json, and ~/.nix-profile/bin on the nix user's path; repo tooling is a zix.json whose default target is modules/packages.nix. The critical review's F2 gap (declarations hidden in aspect files) is fixed with an aspect scan and a removal guard [S5][S6]. The second-repo proof the review asked for is this integration: nix flake check is clean, nix build .#zix builds, and the add/rm round trip parses.

3. The Railway image

Base choice was measured, not assumed: alpine with apk add nix is 44.2 MiB of image against 235.4 MiB for debian-slim with the official installer and 561.6 MiB for nixos/nix [S14]. The published reference image is 588.7 MB of compressed layers across 76 layers [S2]. The agent is never reachable off loopback and the password gate cannot be switched off, mirroring the reference's proven posture [S3][S4]. One deliberate improvement over the reference: /healthz is proxied to the agent port, so a dead agent fails the deploy instead of being masked by a static 200.

Correction log

  • The review's "the fast path skips evaluation entirely" became "skips nixpkgs evaluation" after a counter-measurement counted 233 evaluated files on the eval road versus 6-7 flake files on the fast road [S5][S15].
  • A wave-1 note that unfree packages throw on the fast path was refuted by execution: vscode substituted from cache.nixos.org, exit 0 (wave-2 addendum).
  • zix's eval-road ref shape was wrong in the first implementation (mixed the fast prefix); a test now pins both ref shapes and the fixed form was verified against the index.
  • The entrypoint's first Caddyfile generation ate the bcrypt hash's dollar signs through shell expansion; caught by the auth gate before shipping (quoted heredoc plus Caddy env placeholders).
